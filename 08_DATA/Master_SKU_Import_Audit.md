## ۱. خلاصه اجرایی و فلسفه مواجهه با دیتاست (Executive Summary)
فایل `backup_no_images.json` شامل **۶۸,۷۰۷ رکورد کالایی** به عنوان «کاتالوگ مرجع هویتی» (Identity Reference Catalog) وارد پروژه پُل شده است. هدف بنیادین این دیتاست، تغذیه اولیه لایه هویت محصول (Product Identity Layer) است تا بنکدار هنگام ورود موجودی به سامانه، نیازی به تایپ دستی عناوین نداشته و با اسکن بارکد یا جستجوی سریع، کالا را پیدا و پیشنهاد فروش خود را ثبت کند.

**اصل بنیادین حاکمیت داده (Non-Negotiable Provenance Rule):**
> این دیتاست صرفاً یک **مجموعه داده مرجع هویتی (Identity Reference Catalog)** است:
> 1. این دیتاست **موجودی جاری پُل (Current POL Inventory) نیست**.
> 2. این دیتاست **موجودی بنکداران (Vendor Inventory) نیست**.
> 3. این دیتاست **قیمت روز بازار یا پلتفرم پُل (Current POL Price) نیست**.
> 4. این دیتاست **اعتبار یا سیستم رتبه‌بندی پُل نیست**.
> 5. این دیتاست **یک کاتالوگ تجاری کامل B2B نیست** (زیرا فاقد بارکد و اوزان بسته‌بندی کارتن است).
>
> کلیه فیلدهای غیراپراتوری مبدا نظیر قیمت ریالی اسکرپ‌شده، موجودی قدیمی، امتیاز و نظرات، منحصراً در جدول ایزوله `product_reference_metadata` به عنوان لاگ مبدأ نگهداری می‌شوند و هرگز در فرآیندهای تجاری، سبد خرید، فاکتور یا موجودی استفاده نخواهند شد.

## ۲. تعاریف و روش‌شناسی محاسبه سنجه‌ها (Metric Definitions & Calculation Methodology)

جهت تضمین صحت آماری و حذف هرگونه ابهام میان تعداد «عناوین متمایز» و تعداد «رکوردهای مشمول تکرار»، فرمول‌های زیر در اسکریپت بازرسی اعمال شده‌اند:

1. **عناوین خام یکتا (`raw_unique_titles`):**
   - *تعریف:* تعداد کل رشته‌های عنوان فارسی منحصر‌به‌فرد بدون هیچ‌گونه دستکاری نویسه‌ها.
   - *فرمول:* `len(set(titleFa))`
2. **عناوین خام تکرار شونده (`raw_duplicate_unique_titles`):**
   - *تعریف:* تعداد مقادیر متمایز عناوینی که بیش از یک بار در دیتاست ظاهر شده‌اند.
   - *فرمول:* `count(distinct titleFa where count(titleFa) > 1)`
3. **رکوردهای مشمول عناوین خام تکراری (`raw_records_belonging_to_duplicate_titles`):**
   - *تعریف:* مجموع رکوردهایی که عنوان آن‌ها تکراری است.
   - *فرمول:* $\sum \text{count}(\text{titleFa}) \quad \forall \text{titleFa with count} > 1$
4. **روش نرمال‌سازی رسم‌الخط فارسی (`normalize_persian_text`):**
   - تبدیل حروف عربی «ي» و «ك» به فارسی «ی» و «ک».
   - تبدیل «ة» به «ه».
   - حذف اعراب، تنوین، فتحه، ضمه، کسره، سکون، تشدید (`[\u064B-\u065F\u0670]`).
   - تبدیل نیم‌فاصله‌ها (`\u200c`) و فواصل متوالی به یک فاصله استاندارد.
   - تبدیل اعداد فارسی و عربی به ارقام انگلیسی لاتین.
   - حذف فواصل زائد ابتدا و انتها و تبدیل به حروف کوچک.
5. **عناوین نرمال‌شده یکتا (`normalized_unique_titles`):**
   - *تعریف:* تعداد کل عناوین منحصر‌به‌فرد پس از اجرای الگوریتم نرمال‌سازی فوق.
6. **عناوین نرمال تکرار شونده (`normalized_duplicate_unique_titles`):**
   - *تعریف:* تعداد مقادیر متمایز عناوین نرمال‌شده‌ای که بیش از یک بار تکرار شده‌اند.
7. **رکوردهای مشمول عناوین نرمال تکراری (`normalized_records_belonging_to_duplicate_titles`):**
   - *تعریف:* مجموع رکوردهایی که عنوان نرمال‌شده آن‌ها تکراری است.

## ۶. نگاشت فیلدهای خام به پایگاه داده و رفع کامل موجودیت شبح (Schema Mapping)

پیش از این، در مستندات به موجودیت فرضی `reference_source_metadata` اشاره شده بود بدون آنکه جدولی برای آن در DDL وجود داشته باشد. این تناقض در نسخه ۲.۱ با ایجاد جدول فیزیکی `product_reference_metadata` برطرف گردید:

```sql
CREATE TABLE IF NOT EXISTS product_reference_metadata (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    product_id UUID NOT NULL REFERENCES products(id) ON DELETE CASCADE,
    source_name VARCHAR(50) NOT NULL DEFAULT 'DIGIKALA_CATALOG_EXPORT',
    external_id VARCHAR(100) NOT NULL,
    raw_observed_price_rials BIGINT,
    raw_stock_count INTEGER,
    raw_rating DECIMAL(5, 2),
    raw_reviews_count INTEGER,
    source_url TEXT,
    scraped_at TIMESTAMPTZ,
    imported_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT uq_product_reference_source UNIQUE (product_id, source_name)
);
```

| فیلد خام منبع | نوع مبدا | جدول و ستون فیزیکی در PostgreSQL 18 | ماهیت معماری |
| :--- | :--- | :--- | :--- |
| `dkpId` | Integer | `product_reference_metadata.external_id` | شناسه ردیابی در منبع مبدا |
| `barcode` | String | `product_identifiers.identifier_value` | در فایل ۱۰۰٪ خالی است؛ در محل توسط بنکدار ثبت می‌شود |
| `titleFa` | String | `products.canonical_name_fa` | نام استاندارد کالا پس از نرمال‌سازی فارسی |
| `category` | String | `categories.name_fa` | درخت کاتالوگ رسمی پُل |
| `subcategory` | String | `subcategories.name_fa` | زیردسته‌بندی رسمی متصل به دسته والد |
| `brand` | String | `brands.name_fa` | برند استاندارد؛ تفکیک «متفرقه» |
| `priceRials` | Integer | `product_reference_metadata.raw_observed_price_rials` | متادیتای خام ایزوله؛ به هیچ وجه قیمت بنکدار نیست |
| `stockCount` | Integer | `product_reference_metadata.raw_stock_count` | متادیتای خام ایزوله؛ ربطی به انبار زنده بنکدار ندارد |
| `rating` | Float | `product_reference_metadata.raw_rating` | متادیتای خام ایزوله؛ ربطی به سیستم اعتبار پُل ندارد |
| `reviewsCount`| Integer | `product_reference_metadata.raw_reviews_count` | متادیتای خام ایزوله |
| `specifications`| JSONB | `products.description` / ستون‌های فیزیکی | استخراج ابعاد، وزن و مشخصات فنی |
| `url` | String | `product_reference_metadata.source_url` | لاگ منبع جهت ممیزی و منع اسکرپ مجدد |
| `scrapedAt` | Timestamp | `product_reference_metadata.scraped_at` | برچسب زمانی استخراج از مبدا |

## ۷. خطوط قرمز مالکیت معنوی و عدم اسکرپ (Legal & Provenance Boundaries)

1. **پرهیز مطلق از اسکرپ مجدد (Strict No-Scraping Policy):** سیستم و ایجنت‌ها تحت هیچ شرایطی به وب‌سایت‌های خارجی درخواست اسکرپ ارسال نمی‌کنند.
2. **پایان وابستگی به URLهای خارجی:** نرم‌افزار پُل در هیچ کلاینت، رابط کاربری یا API از URLهای سایت منبع استفاده نمی‌کند.
3. **تصاویر مجاز محصولات:** منحصراً از مسیرهای قانونی عکس‌برداری در شهرک بنکداران اهواز (`VENDOR_UPLOADED`)، کاتالوگ بدون واترمارک تولیدکنندگان (`MANUFACTURER_PROVIDED`) یا تیم بازبینی پُل (`POL_OWNED`) تأمین و با فرمت فشرده WebP در فضای شی‌محور MinIO ذخیره می‌شوند.
