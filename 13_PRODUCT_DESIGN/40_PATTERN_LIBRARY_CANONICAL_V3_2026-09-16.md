# POL Pattern Library v3

## Pattern P01 — Retailer Home
Order: today actions → open orders → reorder → saved lists → search/categories → optional evidence-backed promotion.
Rule: no generic hero carousel above operational tasks.

## P02 — Search Results
Search context stays visible. Results expose Product → Pack → MOQ → Price → Availability → Vendor → Quantity. Filters are progressive, not permanently dominant.

## P03 — Product Detail
Identity first. Commercial facts second. Quantity and add-to-basket action stay visible without scrolling on a standard mobile viewport where practical.

## P04 — Vendor Comparison
Comparison is factual, not ranking-driven. Show explicit trade-offs and allocation impact.

## P05 — Basket
User sees all lines, quantities, vendor allocation, changes/exceptions and final total before commitment.

## P06 — Allocation Review
Explain what changed and what each vendor supplies. Collapse algorithm mechanics.

## P07 — Checkout Confirmation
One final review region. Direct settlement language must identify counterparties; do not mimic a wallet/escrow.

## P08 — Order Group
Parent order group summarises global state; child orders expose vendor-specific state and actions.

## P09 — Reorder
Reuse historical basket, then explicitly surface changes in availability, price, pack or constraints.

## P10 — RMA / Dispute
Progressive flow: select order → issue → items/qty → evidence → submit → track. Keep selected context throughout.

## P11 — Vendor Work Queue
Actionable queue above KPI summaries. Every row ends with a clear next action.

## P12 — Inventory Confirmation
Review → edit/confirm → submit → receipt. Avoid navigation-heavy workflows.

## P13 — Ops Queue
Severity/reason + age/SLA + object + owner + next action. Saved filters for recurring work.

## P14 — Object Detail
Header state + critical facts → timeline/audit → evidence → permitted actions → linked objects.

## P15 — Field Today
Task list grouped by urgency/time. Offline/degraded status remains visible.

## P16 — Network Degraded
Never silently fail. Show unsent action, last sync, retry and duplicate-prevention feedback.

## P17 — Corporate Proof
Problem → how POL works → asset-light model → pilot proof → explicit CTA. No unsupported claims.

## P18 — Error Recovery
Preserve inputs, explain error, focus summary for form errors, offer immediate recovery.

## P19 — Confirmation / Destructive Action
State what will happen, identify affected object, offer cancel, avoid ambiguous primary CTA labels.

## P20 — Dense Table to Mobile
Convert rows into stacked information groups; preserve state, age, reason and next action. Do not merely horizontally compress unreadable columns.
