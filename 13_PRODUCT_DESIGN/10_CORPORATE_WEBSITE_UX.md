# Phase 6 — POL Corporate Website UX

## Goal
Create a high-trust public site that explains POL clearly to retailers, vendors, partners and investors without making unsupported operational promises.

## Primary journeys
### Retailer
Landing → understand value → see how ordering works → join / request activation.

### Vendor
Landing → understand digital catalog/order/referral value → contact/join pilot.

### Partner/investor
Landing → market/problem → platform model → operating architecture → pilot geography → contact.

## Page architecture
- Home
- For Retailers
- For Vendors
- How POL Works
- Ahvaz Pilot
- About POL
- Contact

## Home hierarchy
1. One clear value proposition.
2. The traditional-trade problem.
3. How POL connects retailers and vendors.
4. Why POL is asset-light.
5. How ordering/fulfillment works.
6. Proof/evidence where actually available.
7. Pilot CTA.

## Content governance
Claims must be classified internally as evidence, validated capability, target or hypothesis. Website copy must never convert D-007 or other business hypotheses into guaranteed outcomes.

## Acquisition
Primary CTA should be matched to visitor type: retailer, vendor or partner. Referral/activation links can deep-link into onboarding later, but the public site must remain useful without requiring account creation.
