# POL Screen Composition Rules v3

## Global composition
Every screen follows this order unless task evidence requires another arrangement:
1. context/navigation
2. page title + concise purpose
3. primary task region
4. critical constraints/state
5. secondary information
6. recovery/support
7. persistent navigation where applicable

## Retailer mobile 390×844
- Horizontal padding: 16.
- Safe content width: 358.
- Top context/header region: 56–72.
- Primary decision/action should enter viewport early.
- Bottom navigation reserved for top-level destinations only.
- Cards are optional; rows preferred for repeat commerce.
- Sticky CTA only when it prevents excessive scrolling for a high-frequency commitment action.

## Vendor/Ops desktop 1440×1024
- 12-column conceptual grid.
- Side navigation 240–272; content max width determined by task density.
- Page header 64–88.
- Queue/table gets priority vertical space over KPI decoration.
- Detail side panel only when contextual action is faster than navigation.

## Field mobile
- 16px horizontal padding.
- One task group at a time.
- Every offline/degraded condition visible near the action it affects.
- No tiny controls that require precise tapping.

## Corporate 1440 desktop
- Maximum content width 1200–1280.
- Larger typographic scale and wider vertical rhythm than operational UI.
- B Lotus may be used for display headings.
- Product/photography supports comprehension, not decoration.

## Hierarchy rules
- One primary visual anchor per screen.
- Use size, position, weight and whitespace before color for hierarchy.
- High-risk or state-changing actions require stronger confirmation than routine actions.
- Never make every card visually equal; visual equality implies equal importance.

## Density rules
Comfortable: retailer and field.
Compact: vendor and most ops.
Dense: audit/reconciliation only.

## Content rules
- Persian labels first.
- Keep button labels action-oriented.
- Avoid unexplained English product jargon.
- Use numerals consistently with the locale policy.
- Currency formatting must make unit/pack relationship explicit.
